## 2026-11-03 — addendum 2: implementation bug in the plateau rule, found AFTER the first validation looks (disclosed in full)
- Bug: my first implementation scored cells by mean(self + existing neighbours); edge cells average over fewer, so they were favoured
  (e.g. risk-layer k=3.0, the edge of {2, 2.5, 3}, beat the true centre k=2.5; A2 L=50, A3 corner, B2h p=90 edge). The protocol says "centre of the
  widest stable region", so edge picks were wrong.
- Correction (a faithful implementation of the written rule, derived from train data only): a cell is eligible only if it is interior on every axis
  that has >=3 values; among eligible cells that beat the baseline's train Sharpe, pick the highest mean over self + neighbours.
- Because the first picks had already been validated, the corrected picks use the SECOND (last) validation look, only where the pick changed.
  Where the corrected pick equals the earlier one, no new look is taken. Results of both looks are reported. Selection-bias warning: I had seen
  the first validation numbers before correcting; the correction was mechanical, but the reader should weigh that.
- Also: an optional risk component "earns its place" only with train Sharpe up >= 0.02 AND MaxDD better by >= 0.25 points vs the preceding stage
  (a noise floor; the first run kept a daily loss limit that changed nothing). The frozen spec from the first run (k=3.0) was discarded before any test access.
